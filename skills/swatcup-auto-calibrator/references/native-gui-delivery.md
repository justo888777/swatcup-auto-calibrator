# Native GUI delivery

## Bake direct-only inputs

After accepting direct edits, make the project root the verified state and copy the same touched input files into `Backup/` and `DirectBase/` with `sync_baked_inputs.py`. Do this only for the explicitly accepted files. Re-run the best model after synchronization.

Keep GUI-active parameters to syntax and extensions proven to work with the project's native `Swat_Edit.exe`. Arrays in `.sol`, monthly WUS fields, and reservoir controls may work in the direct runner while failing in native Swat_Edit; bake them when native support is uncertain.

## Preserve the native launch path

- Use the project's original `SUFI2_Pre.bat`, `SUFI2_Run.bat`, and `SUFI2_Post.bat` unchanged when possible.
- Keep `Echo/`; some native projects fail without it.
- Keep `par_inf.txt` and `SUFI2_swEdit.def` in Windows CRLF. Old Fortran readers can reject LF-only control files.
- Ensure declared parameter/simulation counts match the actual parameter rows, every `par_val.txt` row width, run IDs, and the `SUFI2_swEdit.def` interval.
- Preserve the actual SWAT and SUFI2 executables used by the working source project.

## Multi-row smoke test

Make a separate full copy of the formal project. Configure a small multi-row plan whose size is chosen for the current task, then run the native BAT sequence in an interactive terminal. The first Pre/SWAT run can be slow, especially after changing reservoir record modes; allow a realistic cold-start interval.

Run through `SUFI2_Run.bat`/`SUFI2_execute.exe`, not by invoking `Swat_Edit.exe` alone. The executor supplies the sampled parameter row and tracking context. A standalone editor launch can appear successful while applying zero values. Legacy `Swat_Edit.exe` also expects a usable console handle; `capture_output`, redirected streams, or a hidden non-PTY subprocess can hang before writing its log. Use an interactive terminal/PTY and save the resulting editor log as evidence.

The smoke test passes only when:

- Pre completes and applies every smoke-plan parameter row;
- Run completes the configured number of SWAT simulations;
- every variable in the current `observed_rch.txt`—for example `FLOW_*` and `SED_*`—contains exactly the configured number of blocks with that variable's correct observed index/length, including non-contiguous indices for sparse sediment observations;
- Post produces its objective/goal and 95PPU outputs;
- the first run reproduces the baked best model within expected numeric precision.
- the editor log contains the intended first-row value for the first active parameter, reports a real change in at least one representative target file, and contains the intended value for a tail parameter.

Use a best-series CSV generated by the current index-preserving runner. Historical series without `VARIABLE__INDEX` rows cannot prove alignment for sparse observations; regenerate them with a deterministic best-model replay instead of assuming row order.

Also validate the longest `par_val.txt` row through the project's native input-builder path and compare the generated `model.in` values, especially the final parameters. Legacy line buffers can silently drop tail values even when Pre exits successfully; do not encode a universal parameter-count limit—measure the active project. Confirm the native editor log reports actual edits to representative target files.

Archive the smoke receipt outside the formal `SUFI2.OUT/`. Restore the user-requested formal simulation count, full `par_val.txt`, and matching `SUFI2_swEdit.def` interval, then leave formal `SUFI2.OUT/` empty. A smoke-sized plan left in the formal project can make GUI Run appear to do nothing or execute the wrong count. Run `native_gui_check.py --strict` as the final release-boundary check.

Clear generated `SUFI2.OUT/` files before formal delivery. Native Pre tools can issue a confirmation prompt before deleting an existing ensemble; in a GUI-launched or redirected process that prompt can look like a frozen first parameter. Keep the smoke log and extracted evidence in a separate validation directory, not in formal `SUFI2.OUT/`.

Also clear `SUFI2.OUT/` before every smoke extraction, not only at delivery. Some legacy extractors append to existing variable files. After the smoke, restore the accepted `model.in`; the file left by the smoke or last sampled row is not evidence of the baked best state.

Pass `--expected-formal-runs`, the smoke output, the verified best process-series CSV, and `--native-edit-log`. Static checks verify non-empty native executables, matrix shapes, and sampled editor values; they supplement but never replace actually executing the original BAT sequence.
